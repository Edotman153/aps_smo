# Имитационная модель СМО

Модель системы массового обслуживания: источники заявок, буфер конечной ёмкости и несколько приборов обслуживания. Симулятор написан на C++ (потоки, реальное время), результаты смотрятся в окне на PyQt6.

```
источники  ->  приём  ->  буфер (10 мест)  ->  диспетчер  ->  приборы (7 шт.)
```

## Как работает модель

- **Источники** (5 штук) создают заявки через 50 или 100 мс (равновероятно). Приоритет источника равен его номеру: чем больше номер, тем выше приоритет.
- **Приём** забирает заявки по очереди и кладёт их в буфер.
- Если **буфер полон**, новая заявка занимает место последней лежащей в нём, а вытесненная считается отказом.
- **Диспетчер**, когда есть заявка и свободный прибор, выбирает заявку с наибольшим приоритетом (при равных самую раннюю) и отправляет на свободный прибор. Приборы перебираются по кругу, указатель сдвигается после каждой отправки.
- **Прибор** обслуживает заявку случайное время (экспоненциальное распределение, среднее 100 мс).

Параметры (число источников, размер буфера, число приборов, средние времена) заданы константами в начале `main.cpp`.

## Запуск

Нужны компилятор C++17, CMake и Python 3.10+.

```bash
pip install -r requirements.txt
./run.sh            # соберёт симулятор, прогонит 15 секунд и откроет окно с таблицами
./run.sh 30         # то же на 30 секунд
```

То же вручную:

```bash
cmake -S . -B build && cmake --build build
./build/smo out 15          # результаты запишутся в каталог out/
python main.py out          # показать таблицы
```

Без CMake: `g++ -std=c++17 -O2 main.cpp -o smo -pthread`. На Windows подойдёт тот же CMake (Visual Studio или MinGW), только запускать надо `build\Release\smo.exe`.

### Параметры симулятора

```
smo [каталог_результатов] [секунд] [--quiet]
```

| Параметр | Значение |
|----------|----------|
| `каталог_результатов` | куда записать `banks.txt` и `familys.txt` (по умолчанию текущий, создаётся при необходимости) |
| `секунд` | длительность моделирования (по умолчанию 15) |
| `--quiet`, `-q` | не печатать ход моделирования в консоль |

Без `--quiet` симулятор выводит каждое событие: создание, постановку в буфер, отказ, отправку на прибор, окончание обслуживания.

## Результаты

В окне две таблицы.

**Источники:**

| Колонка | Смысл |
|---------|-------|
| Количество заявок | всего заявок источника (обслужено + отказов) |
| p | вероятность отказа: отказы / количество заявок |
| Отказы | заявок, вытесненных из буфера |
| Тпреб | среднее время пребывания в системе, мс (Тбп + Тобсл) |
| Тбп | среднее время ожидания в буфере, мс |
| Тобсл | среднее время обслуживания, мс |
| Дбп, Добсл | разброс времени ожидания и обслуживания |

В колонках Дбп и Добсл по умолчанию стандартное отклонение. Ключ `--variance` (`python main.py out --variance`) переключает их на дисперсию.

**Приборы:** коэффициент использования, то есть доля времени, в которую прибор обслуживал заявки.

### Формат файлов

`familys.txt`, три строки на источник:

```
USER 0 statistic: ALL: 196 success: 177 declined: 19
waitDurations: 131 32 139 ...        время ожидания в буфере каждой отправленной заявки, мс
Processing durations: 9 33 25 ...    время обслуживания каждой обслуженной заявки, мс
```

`banks.txt`, строка на прибор: `Bank 0 0.857114`.

## Замечания

- Моделирование идёт в реальном времени и использует случайные числа без фиксированного seed, поэтому результаты от запуска к запуску немного отличаются. На сильно загруженной машине времена искажаются.
- Заявки, которые в момент остановки ещё обслуживаются, в статистику обслуживания не попадают (в ожидание попадают). Поэтому число записей об обслуживании может быть меньше числа обслуженных заявок, но не более чем на число приборов.

## Тесты

```bash
pip install -r requirements-dev.txt
cmake -S . -B build && cmake --build build
pytest
```

Тесты проверяют разбор файлов и (если симулятор собран) настоящий двухсекундный прогон: согласованность счётчиков, диапазон коэффициентов, самостоятельное завершение программы.

## Файлы

- `main.cpp` - симулятор
- `main.py` - окно с таблицами
- `smo_stats.py` - чтение результатов и подсчёт показателей
- `CMakeLists.txt`, `run.sh` - сборка и запуск
- `tests/` - тесты
